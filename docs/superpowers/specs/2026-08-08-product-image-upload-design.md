# Product Image Upload — Design Doc

Date: 2026-08-08
Status: Approved

## Problem

Product images in the DB are base64 data-URI placeholder SVGs (generated by
`server/src/utils/imagePlaceholder.ts`). There is no upload endpoint, so admins
cannot attach real product photos. The goal: admins can upload real images and
see them render on the storefront.

## Scope (decided with user)

- **Product images only.** Review/category/avatar images stay as-is.
- Existing 12 products keep their placeholder SVGs; the user uploads real
  photos manually via the admin product form.

## Approach: Local upload via multer + static `/uploads`

### Server (`server/`)

1. Add `multer` (only new dependency).
2. Create `server/uploads/` directory (gitignored).
3. New endpoint `POST /api/upload`:
   - Require auth + admin.
   - Accept a single `image/*` file, max ~2MB.
   - Save with a unique filename (`<timestamp>-<random>.<ext>`).
   - Return `{ url: "/uploads/<filename>" }`.
4. Serve statically: `app.use('/uploads', express.static(<uploads dir>))`.
5. Optional `UPLOAD_DIR` in `.env` (defaults to `server/uploads`).

### Client (`client/`)

1. Rewrite `client/src/components/admin/image-upload.tsx`:
   - Replace `FileReader.readAsDataURL` with a `FormData` upload to `/api/upload`.
   - Store the returned `/uploads/<filename>` string in `images[]`.
2. Add helper `resolveImageUrl(img)` (in `client/src/lib/utils.ts`):
   - `data:` or `http(s)://` prefix → return unchanged (placeholders keep working).
   - `/uploads/...` prefix → prefix with API origin (`VITE_API_URL`).
3. Wrap every site that renders a product image with `resolveImageUrl()`:
   product card, product detail page, cart drawer, order items, wishlist,
   admin products table, account pages, home sections, etc.

### Data flow

Admin uploads photo in product form → file POSTed to `/api/upload` → server
returns `/uploads/abc.jpg` → path saved in `product.images[]` → storefront
renders it via `resolveImageUrl()`.

## Verification

- Admin logs in → edits a product → uploads `.playwright-mcp/test-img.png` →
  save → photo shows on storefront card + detail page.
- `GET /uploads/...` returns the image bytes.
- Client and server production builds pass.
- Placeholder-only products still render (data URIs pass through unchanged).

## Notes

- No git repo in this project, so no commit step.
- `resolveImageUrl` keeps DB portable (relative paths), at the cost of touching
  all render sites — accepted trade-off.
